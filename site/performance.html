Performance

Small on disk. Quick to start. Still when idle.

Every time Volant is built, GitHub's Apple Silicon machines launch it next to Safari, Chrome and Firefox, open the same five pages in each, and measure them. These are the latest results.

App size

Megabytes on disk. Smaller is better.

Memory, five pages

Megabytes, all processes. Lower is better.

Volant draws pages with the same engine as Safari, so page loading and JavaScript run at Safari's speed, and memory lands in Safari's range. Safari's app is small for the same reason Volant's is: its engine ships inside macOS.

Why it's fast

Mostly, by not doing things.

{{icon:bolt}}

The window comes first

Volant puts its window on screen before it starts WebKit for your first tab, so you see the browser in a third of a second.

{{icon:box}}

No engine in the box

WebKit already ships with macOS, and it's usually already in memory. Volant's download is the browser around it, and nothing else.

{{icon:moon}}

Sleeping tabs

Tabs you haven't looked at in a while give their memory back. With 20 tabs open, most of them cost almost nothing.

{{icon:shield}}

Blocking ahead of time

uBlock's filters are compiled once, so WebKit matches requests natively instead of asking a script about each one.

{{icon:code}}

Plain files

History is an append-only log and settings are a text file. There's no database to open at launch.

{{icon:eye}}

Still when idle

Volant redraws only when something changes, and its housekeeping wakes once a minute. The benchmark checks idle CPU on every build.

Method

How it's measured.

  • Launch to window: from starting the app to its first window being on screen, watched from outside the app. One warm-up launch, then the median of three.
  • Memory: the memory footprint of every process each browser runs (app, web content, networking and GPU), with the same five pages loaded, as Activity Monitor counts it.
  • App size: the app bundle on disk after installing.
  • Idle: the CPU time all of those processes use over 30 seconds with nothing happening, also in the results.

The benchmark is in the repository and runs on every build. Its results are kept with each run.
